## המחזור של כל משימה

```bash
git pull                      # 1. תמיד לפני שמתחילים
# ... עבודה ...
git status                    # 2. לראות מה השתנה
git add -A
git commit -m "..."           # 3. הודעה שמסבירה מה ולמה
git push                      # 4. עבודה שלא נדחפה לא קיימת עבור הצוות
```

הודעת קומיט: שורה ראשונה קצרה באנגלית או בעברית, מה השתנה. גוף ההודעה,
כשצריך, מסביר למה. קומיט אחד לכל שינוי הגיוני, לא קומיט אחד ליום.

## ענפים

- **עבודה על התיעוד** נעשית ישירות על `main`. הצוות קטן, והמסמכים הם
  הזיכרון המשותף; אין טעם לעכב אותם.
- **קוד** נכתב בענף בשם `feature/<נושא>` באנגלית, ומתמזג ל-`main` דרך
  Pull Request. ה-PR הוא המקום שבו צחי נותן חוות דעת לפני מיזוג.
- לא דוחפים בכוח (`--force`) ל-`main`.

## מסמכים לפני קוד, גם ב-Git

הסדר לא השתנה: מסמך ב-`docs/` נכנס לקומיט **לפני** הקוד שהוא מתאר, או
באותו קומיט. קומיט של קוד בלי מסמך שמסביר אותו יוחזר.

## יומן

כל משימה משמעותית מקבלת רשומה ב-`docs/journal/` עם תאריך מוחלט, מה
נעשה ולמה. הרשומה נכנסת לאותו קומיט של העבודה שהיא מתעדת, כך שהיסטוריית
Git והיומן מספרים את אותו סיפור.
