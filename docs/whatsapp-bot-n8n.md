## מה הבוט עושה

```text
הודעה נכנסת (POST /webhook/wellbeing-shop-bot)
  → פענוח: רק הודעות, לא עדכוני סטטוס
  → customers: מי שולח?
      ├─ מספר חדש      → שורה חדשה (שם ריק, שם פרופיל) → "איך קוראים לך?"
      ├─ מחכים לשם     → OpenAI מחלץ שם → עדכון השורה → "נעים מאוד" + תפריט (List)
      └─ לקוח מוכר     → קטלוג מהגיליון + הקשר (המוצר האחרון, 24 שעות)
            ├─ לחיצה על כפתור/רשימה — לפי קידומת המזהה, בלי מודל:
            │     route_* → מסלול · prod_* → פרטי מוצר + [להזמין] [מוצרים נוספים]
            │     order_* → סיכום + [כן, להזמין] [ביטול] · confirm_* → שורה ב-orders · cancel
            └─ טקסט חופשי → פקיד קבלה (OpenAI, JSON)
                  ├─ sales    → תשובה קצרה + רשימת המוצרים הרלוונטיים (List)
                  ├─ order    → "טוב תזמין": סיכום למוצר שבהקשר. בלי הקשר — הקטלוג
                  ├─ support  → בלי פירוט: "ספרו לי" · עם פירוט: שורה ב-orders
                  ├─ fitness  → יועץ כושר כללי
                  ├─ shipping → ההזמנה האחרונה של המספר מ-orders
                  ├─ signup   → קישור הרשמה (זמני)
                  └─ unclear  → שאלת הבהרה + תפריט
  → בניית הודעה (טקסט / List / כפתורים) → שליחה ב-Cloud API → chat_log
```

אימות ה-webhook של Meta (GET) עונה `hub.challenge` רק עם טוקן האימות
הנכון, ו-`forbidden` בכל מקרה אחר.

## החלטות

- **HTTP Request ל-OpenAI ולא צמתי LangChain** — כמו בתרחיש הסדנה
  `סוכן קביעת פגישות`. תשובת JSON (`response_format`) לסיווג ולחילוץ השם.
- **Webhook רגיל ולא WhatsApp Trigger** — ה-Trigger של n8n רושם את עצמו
  אצל Meta בהפעלה, כלומר משנה את הגדרות ה-webhook של האפליקציה. כאן
  החיבור הוא החלטה של תומר.
- **שם ריק = מחכים לשם.** `?` = ניסיון אחד נכשל. ניסיון שני שנכשל — ממשיכים
  עם שם הפרופיל בוואטסאפ, ואם אין — "לקוח". בלי לחסום.
- **שני שמות בגיליון:** `name` — מה שהלקוח מסר לבוט; `whatsapp_name` — שם
  הפרופיל ש-Meta שולחת. לקוח מוכר שחסר לו `whatsapp_name` מקבל אותו
  בהודעה הבאה, בענף מקביל שאינו מעכב את התשובה.
- **רק עמודות הגיליון נכתבות לגיליון.** עדכון במצב `autoMapInputData` כותב כל
  שדה שמגיע אליו, ולכן לפני כל עדכון יש צומת שמשאיר רק את העמודות. בגרסה
  הראשונה נוצרה כך בטעות העמודה `askAgain` ב-`customers`.
- **המחיר והמלאי רק מהגיליון.** הקטלוג נשלף בכל שאלת מכירות ומוזרק לפרומפט.
- **כמות מלאי אינה נמסרת** — "במלאי" / "נשארו מעט" / "אזל".
- **השוואת טלפונים על ספרות בלבד**, וכתיבה לגיליון ב-`RAW`, כדי שמספר לא
  יהפוך ל-`9.7E+11`.
- **כל קריאה ל-OpenAI ולוואטסאפ ממשיכה גם בשגיאה.** תשובת גיבוי ללקוח, והשגיאה
  נרשמת ב-`chat_log`.
- **מגבלות Meta** נבדקו בתיעוד הרשמי ב-23 בספטמבר 2026 ונאכפות בצומת
  "בניית הודעת וואטסאפ": List — עד 10 שורות, כותרת שורה 24 תווים, כפתור 20;
  Reply buttons — עד 3, כותרת 20.

## הזמנה בבוט

- **המוצרים מוצגים כרשימה לבחירה**, לא כטקסט חופשי: סוכן המכירות מחזיר JSON
  עם תשובה קצרה ומזהי המוצרים הרלוונטיים, והבוט בונה מהם List עם מחיר ומלאי
- **הקשר:** המוצר האחרון שנבחר נשמר ב-static data של התרחיש, לפי טלפון, ל-24
  שעות. כך "טוב תזמין" מובן בלי זיכרון שיחה מלא
- **המחיר והמלאי נבדקים שוב ברגע האישור** מול הגיליון. מוצר שאזל בינתיים —
  ההזמנה לא נרשמת
- **שורת הזמנה ב-orders:** `O-yyMMddHHmmss`, מוצר, מחיר, הנחה 0, סטטוס `new`.
  הנציג ממשיך משם
- **המלאי יורד באישור:** אחרי כתיבת ההזמנה, `stock` של המוצר בגיליון החנות
  מתעדכן (לא מתחת ל-0). ביטול אינו מחזיר מלאי אוטומטית
