# בוט החנות בוואטסאפ — קוד המקור של תרחיש n8n

התרחיש רץ ב-n8n: `wellbeing — בוט חנות בוואטסאפ` (`uyHY1LQjC6xlAztj`).
התיעוד המלא — מה הבוט עושה, החלטות ובדיקות: [docs/whatsapp-bot-n8n.md](../../docs/whatsapp-bot-n8n.md).

## מה יש כאן

```text
bot/
├── build.py        # מבנה התרחיש: צמתים, חיבורים, Switch-ים, מיקום על הקנבס
├── code/           # הקוד של כל צומת Code — קובץ לכל צומת
│   ├── 0x-...      # ① קליטה וזיהוי
│   ├── 1x-...      # ② לקוח חדש — היכרות
│   ├── 2x-...      # ③ לקוח מוכר — מה לעשות?
│   ├── 3x-...      # ④ מכירות והזמנה
│   ├── 4x-, 5x-... # ⑤ שירות לקוחות ותמונות
│   ├── 6x-...      # ⑥ כושר · משלוח · הרשמה · הבהרה
│   └── 7x-...      # ⑦ שליחה ורישום
└── prompts/        # ה-system prompt של כל קריאה ל-OpenAI
```

המספרים בשמות הקבצים תואמים לאזורים הממוספרים על הקנבס ב-n8n.

## הסכמות בקוד

- **כל צומת Code נפתח בכותרת:** מה הוא עושה, ומה הוא מחזיר
- **כל תשובה ללקוח** יוצאת באותו מבנה, `{ phone, route, kind, text, ... }`, אל
  הצומת "בניית הודעת וואטסאפ". `kind` הוא `text`, `list` או `buttons`
- **`customer`** הוא תמיד הפלט של "זיהוי לקוח": טלפון, שם, ההודעה
- **Switch-ים עם יציאות בשם** ("מכירות", "תמונה"...), לא לפי מספר
- **המודל מחליט רק מה לענות.** כל פעולה עם הרשאות — כתיבה לגיליון, העלאה
  ל-Supabase — קורית בקוד קבוע, לפי מה שהלקוח לחץ או שלח

## בנייה ופריסה

```bash
cd n8n/bot
python3 build.py
```

בלי משתני סביבה נכתב `../wellbeing-shop-bot.json` עם placeholders במקום
הסודות — זה הקובץ שבגיט. לפריסה בונים עם הערכים האמיתיים
(`META_VERIFY_TOKEN`, `WA_PHONE_ID`, `WA_GRAPH_VERSION`) לקובץ מחוץ לריפו,
ומעלים אותו עם `PUT /api/v1/workflows/<id>` של n8n.

**שינוי ב-n8n עצמו יידרס בפריסה הבאה.** משנים כאן, בונים ופורסים.
